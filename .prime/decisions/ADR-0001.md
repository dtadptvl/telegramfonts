# FAST_30 is the sole production reconstruction/fidelity profile

## Context
The prior BALANCED_MAX/ FULL_MAX strategy with automatic/semi-automatic escalation was producing terminal failures due to lease-heartbeat starvation during long compute. The Human has approved a hard limit on wall time per font and retirement of the fallback/escalation mechanism entirely (no more confidence-triggered or gate-triggered escalation, no operator-triggered escalation). Forgetting this would cause material rework/error in future profiling/validation decisions.

## Decision
FAST_30 replaces BALANCED_MAX as the primary reconstruction profile; FULL_MAX is fully retired from production paths. No fallback/escalation exists across any trigger type. Production outputs are TTF+OTF only, with unchanged final gates. Exact binary/artifact reuse wins immediately. Source acquisition fallbacks are bounded data-source recovery only, not fidelity-profile fallback. Runtime model failover (from v7) is capacity/unavailability only, preserving the unchanged contract and reusable evidence. E2E wall limit is 30 minutes per font; deadline or quality failure returns FAST30_FAILED and stops. Chroot/runtime runtime truths (device-specific mount fixes, NO_LOCAL_ARCHIVE, heartbeat daemon thread, CAS terminal recovery) are preserved.

## Constraints
- Never reintroduce a fallback/escalation path (automatic/manual/background/confidence/gate/operator-triggered).
- No weakening of held-out/thresholds/consumers/validation semantics for FAST_30 validation (but use minimal schedule within the profile's own constraints).
- Maintain exact-match reuse precedence and preserve all deterministic gates.
- Preserve runtime environment correctness: external ext4 off A23, mini-PC target for archive; chroot /proc + bind /dev/{urandom,random,zero} + tmpfs /dev/shm; boot-recovery script 631d2920; worker heartbeat on daemon thread; terminal-FAILED CAS recovery.

## Consequences
- FullMAX lane CI semantics become obsolete (to be adjusted or removed later; currently unused by default).
- PRs #91/#92/#93 (#94 heartbeat fix, CAS extension) remain valid under the new regime if they do not imply escalation/fallback semantics.
- Issue #90 (BALANCED_MAX contract) and live Full-MAX job attempt 6 on A23 are marked stale/incompatible; drains naturally fail-closed.
- Paid order ord_2a142f39 requires fulfillment under the new profile post-restart (monetary handling by Human if unfulfillable).
