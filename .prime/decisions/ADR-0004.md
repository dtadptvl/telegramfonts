# FAST_ATLAS_ULTRA_V1 speed-first rebaseline under the FAST_30 public profile

## Context
T-FAST30-A23-FIX proved the wall/watchdog/zombie hardening works but acceptance failed on duration: the measurement/reconstruction schedule cannot fit the 30-minute wall on A23 (1800.93s consumed without completion). Human priority is now SPEED. This decision rebaselines the reconstruction policy while keeping FAST_30 as the only public compatibility profile name.

## Decision
- Internal policy identity: FAST_ATLAS_ULTRA_V1; public profile name remains FAST_30. BALANCED_MAX and FULL_MAX remain retired; no fallback or escalation of any kind.
- Walls: ORIGINAL hard wall 8 minutes; VIETNAMESE hard wall 12 minutes; wall expiry -> FAST30_FAILED, no retry, no heavier profile.
- Targets: ordinary ORIGINAL 150-250 glyphs 2-5 min; large ORIGINAL 400-500 glyphs 5-10 min; exact binary/model/final-font reuse under 1 minute where practical.
- Acquisition order: (1) exact valid TTF/OTF cache or authorized binary wins immediately; (2) exact canonical FontModel cache builds only missing TTF/OTF; (3) native Chrome --dump-dom for family/style/weight/identifiers/MD5; (4) one persistent Chromium/Playwright session ONLY when metadata, measureText or browser atlas fallback is actually needed; (5) bounded metadata/Algolia resolution when MD5 missing; (6) direct HTTP/Monotype CDN is the primary raster source; (7) browser atlas only for missing or unattestable observations; (8) no screenshot, no per-glyph navigation, no per-glyph CDP rendering.
- Fast raster pass: size 1024, phase x=0/y=0, one logical atlas in bounded pages, target 96 MB hard max 128 MB, one page in memory at a time, HTTP/CDN first, one readback per page, crop cells in memory and release page memory immediately; never pre-collect 512/2048/4096 or extra phases.
- Metrics: batch measureText for the complete glyph set at sizes 512/1024/2048 (width, actual bbox, ascent/descent, font bbox), normalized by multi-size regression to UPEM=1000, a few batched JS calls only, concurrent with HTTP atlas acquisition.
- Fast geometry per glyph: alpha decode -> coordinate normalization -> direct alpha/subpixel contour -> topology cleanup -> cubic Bezier fitting -> error-bounded simplification -> cheap FIT-confidence check. Easy glyphs MUST NOT compute SDF or run the heavy optimizer. Confidence checks: finite/closed contours, sane bbox/advance, topology/hole/component consistency, Bezier residual, metrics-regression residual, catastrophic self-intersection, degenerate segments. PASS freezes the GlyphModel immediately and releases transient memory.
- One refinement only (failed glyphs): add 1024@x=0.5,y=0 and 2048@x=0,y=0; then reuse 1024@x=0 -> merge alpha -> SDF -> local contour/Bezier refit -> bounded local optimizer -> confidence check. No 512, no 4096, no x=0.25/0.75, no second tier, no whole-font optimizer, no whole-font reconstruction retry. After the single refinement: structurally valid best candidate may be accepted even with low visual confidence (recorded as low-confidence glyph IDs in the validation report); structural/outline/shaping/rendering invalidity remains FAILED_GLYPH.
- Streaming and cache: download page N+1 while decoding page N; frozen glyphs inserted immediately into the canonical FontModel. Persistent exact-identity caches: compressed raster observations, metrics, final cubic GlyphModels, canonical FontModel, TTF/OTF, validation report. Ephemeral only: decoded alpha, SDF, temporary contours, merge buffers. Checkpoint after every completed atlas page or 32 frozen glyphs and on graceful shutdown; no fsync per glyph.
- Typography: selective bounded kerning pairs only; GPOS kern only for measured material deltas; preserve liga/calt from authorized binaries; for raster reconstruction create liga/calt only when exact observable mapping is proven; no exhaustive ss01-ss20 probing.
- VIETNAMESE optional path: vietnamese=false skips all Vietnamese work; vietnamese=true: NFC/NFD coverage audit, preserve existing glyphs, deterministic component composition first, infer anchors/mark/mkmk, validate collision/bbox/spacing/NFC-NFD geometry equivalence, deterministic local geometry search only for failed classes, AI only for remaining failed glyph classes (never per glyph, never raster-generating), preserve the approved Woku/OpenRouter cascade and secret boundary (ADR-0003), cap AI calls by glyph class and reuse one StyleProfile, structurally invalid classes fail with no global geometry rerun.
- Font build: canonical cubic FontModel is the single source of truth; OTF via CFF; TTF via cu2qu/glyf; optimize/form once; never independently reconstruct or optimize TTF and OTF; TTF and OTF remain the only outputs.
- Speed-first final validation (run ONCE): FontTools structural/load/table/cmap/metrics/outline checks; HarfBuzz representative shaping/positioning/kern checks; FreeType representative loading/rendering; bounded NFC/NFD + Vietnamese representative corpus checks when Vietnamese selected. After a temporary TTF passes, build final TTF+OTF and run cheap FontTools structural/load checks on both. PROHIBITED: exhaustive Chromium final validation, legacy four-consumer MAX gate, complete MAX held-out schedule, full repository suite, soak, retired FULLMAX/BALANCEDMAX E2E, a second heavy validation pass.
- Runtime defaults (i3-7100 / 8 GB Debian): browser_sessions=1, http_concurrency=8, glyph_workers=2, atlas_pages_in_memory=1, atlas_target_mb=96, atlas_max_mb=128, checkpoint_batch=32; all configuration-driven. Compiled/native NumPy/SciPy/Pillow/FontTools operations for pixel/SDF/contour work; Python orchestrates; no Python per-pixel loops.

## Constraints
- A23 is staging/compatibility only, NOT production performance authority; its runtime claims are stale-prone and must be reconciled read-only before reliance. No worker/Chromium stop/restart, no release deploy, no D1/Queue/R2, no failed-order recovery, no production job under this decision.
- Preserve T-FAST30-A23-FIX hardening: job-level wall (re-targeted to 480s/720s), supervisor watchdog, durable checkpoints, edge age backstop/zombie prevention.
- No A23-specific hardcoding that prevents the Debian Mini PC migration.

## Consequences
- Earlier exhaustive-MAX-era validation expectations no longer bind; low-confidence glyph IDs are an accepted, reported outcome class.
- Deployment of this line remains separately authorized (this decision grants no production deployment or order-recovery authority).
- ADR-0001 keeps its profile-retirement semantics (FAST_30 sole public profile; BALANCED_MAX/FULL_MAX retired; no fallback/escalation); only its performance/validation regime parts are superseded here.
